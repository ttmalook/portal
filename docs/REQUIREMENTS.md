## 1. 개요

### 1.1 목적
보안 파트너사가 고객 도메인의 **외부 관측 보안 리스크(SecurityScorecard)**를 정리하고, 표준 **검증랩**에서 같은 문제의 조치 전·후를 재현해 참고 증적을 만들며, 이를 **고객 리포트**로 전달하기까지의 전 과정을 하나의 시스템으로 제공한다.

### 1.2 범위
- **In scope**: SSC 리스크 수집(읽기 전용) · 검증랩 조치 전후 재현(참고 PoC) · 조치 가이드 · 증적 팩 · 고객 리포트 전달 · 인증/권한/감사 · 관리자용 AI Lab Builder.
- **Out of scope**: 고객 운영환경에 대한 실제 조치 수행/원격 제어 · SSC 데이터 쓰기 · 실시간 관제(SIEM) · 결제.

### 1.3 용어
| 용어 | 정의 |
|---|---|
| SSC | SecurityScorecard — 외부 관측 기반 보안 평가 서비스(읽기 전용 연동) |
| 검증랩 | Docker 격리 스택에서 취약↔조치를 재현해 참고 증적을 만드는 환경 |
| 증적 팩 | 고객 전달 단위로 묶은 검증랩 증적 + 조치 권고 + 리스크 |
| apex 도메인 | 최상위 도메인(예: `posco.co.kr`). SSC 스코어카드의 키 기준 |

## 3. 기능 요구사항 (FR)

| ID | 기능 | 요구사항 |
|---|---|---|
| **FR-01** | 인증·세션 | 이메일/비밀번호 로그인(scrypt 저장). Access JWT + Refresh 쿠키(회전·재사용 탐지). 세션(기기) 조회·원격 폐기. 비밀번호 변경(8자+3종 이상, 변경 시 전 세션 폐기) |
| **FR-02** | 권한(RBAC) | 리소스별 read/write 매트릭스. 프론트 버튼 게이팅 + 백엔드 `requirePerm` 403 **이중 게이트**. 권한 거부는 보안 감사 기록 |
| **FR-03** | 고객사 관리 | 고객사 등록/수정/삭제. 필수: 고객사명. 담당자(고객담당자)·이메일·산업군·계약상태·메모 |
| **FR-04** | 도메인·점검 범위 | 도메인 등록(고객사 + 서비스 주소 필수). 저장 시 SSC 조회 기준 **apex 정규화**(스킴·포트·경로·`www.` 제거). 점검 허용/제외 URL |
| **FR-05** | 리스크 점검(SSC 수집) | 도메인별 SSC active-issues **읽기 전용** 수집. 점수/등급 · 조치 우선순위(점수 개선 여력 순). 자산 URL 위생 처리(쿼리·자격증명 제거). 조회 전 스코프 확인 |
| **FR-06** | 검증랩 재현 | 리스크 항목 → Docker 격리 타깃에서 조치 전·후 재현, 증적 캡처. 증적 5단계(개요·조치 방법·조치 전/후·관측값·확인·마무리). 대표 증적 지정. 참고 PoC임을 명시 |
| **FR-07** | 조치 가이드 | 검증랩 미지원 유형에 4단계 가이드(개요·조치 방법·검증·마무리). 엔진별 조치·검증 명령·컴플라이언스. AI 쉬운말 요약(캐시 재사용) |
| **FR-08** | 증적 팩 | 고객사별 증적 묶음(검증랩 증적 + 조치 권고 + 리스크). 전달 포함/제외 |
| **FR-09** | 고객 전달 | 전달 대상 리스트 → 새 창 리포트 뷰어(검토→전달). **리포트 HTML 내보내기**(자립형 단일 HTML, 폰트·이미지 임베드, **선택적 열람 암호 AES-256-GCM**). 이메일(mailto) |
| **FR-10** | 감사 로그 | 사용자·보안·시스템 이벤트 기록(종류 필터). **토큰·비밀번호 등 민감값 미기록** |
| **FR-11** | 사용자·설정 관리(admin) | 계정 생성·역할·비밀번호 재설정. 마지막 관리자 강등/삭제 차단. **SSC API 토큰 설정(AES-256-GCM, 원문 미노출)** |
| **FR-12** | 랩 스튜디오(AI Lab Builder, admin) | SSC 신규 유형 → 분류 → 레시피 컴파일(Claude, 데이터만) → 결정적 렌더 → 게이트 → 관리자 승인 → immutable 채택 |

## 4. 비기능 요구사항 (NFR)

| ID | 분류 | 요구사항 |
|---|---|---|
| **NFR-01** | 보안 | 비밀번호 scrypt, refresh 원문 미저장(해시+회전+재사용 탐지), 시크릿(SSC·Claude) AES-256-GCM 저장·원문 미반환, 감사 민감값 미기록, **HTTPS 필수**, 리포트 선택적 암호화 |
| **NFR-02** | 성능·용량 | 복구 목표 RTO 10분, 동시 사용자 ~5명(소규모), HA 미적용 |
| **NFR-03** | 가용성 | DB 연결 실패 시 **파일 저장소 자동 폴백**(앱 무중단), 컨테이너 `unless-stopped` 자동 복구 |
| **NFR-04** | 이식성 | Docker Compose 배포(단일 호스트 / 3-VM), 환경변수 기반 설정 |
| **NFR-05** | 데이터 | 운영 = JSONB 문서 스토어(10 테이블), 리포팅 타깃 = 정규화 스키마(6 테이블). 스키마·명세는 [DATABASE.md](DATABASE.md) |
| **NFR-06** | 감사성 | 주요 쓰기·인증·권한 이벤트를 append-only 감사 로그로 기록 |

## 5. 제약 · 가정

- **SSC 연동은 읽기 전용** — 수집만 하며 SSC에 쓰지 않는다.
- **검증랩 증적 = 참고 PoC** — 고객 운영환경의 실제 해소를 의미하지 않으며, 공식 확인은 **SecurityScorecard 재스캔**으로 한다.
- SSC 스코어카드는 **apex 도메인 기준**으로 키가 잡힌다(`www.` 정규화 필요).
- **AI Lab Builder 신뢰 경계**: Claude는 스키마 고정 **레시피(데이터)만** 생성하고 실행 코드를 만들지 않는다. 채택은 게이트 통과 + 관리자 승인 후 immutable 버전으로만 이뤄진다.
- 프로덕션 부팅 시 `AUTH_ACCESS_SECRET`·`SEED_ADMIN_PASSWORD` 미설정/기본값이면 기동을 거부한다(안전장치).
