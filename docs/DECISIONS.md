# 의사결정 기록 (DECISIONS / ADR)

**"왜 이렇게 만들었나"** — 코드를 봐도 복원되지 않는 맥락을 남긴다. 후임이 구조를 바꾸기 전에 반드시 여기서 배경·트레이드오프를 확인할 것. 진입점은 [HANDOVER](HANDOVER.md).

> 형식: 결정 / 배경 / 근거 / 트레이드오프 / 상태.

---

## ADR-01 · 운영 저장소로 JSONB 문서 스토어 + 파일 폴백

- **결정**: 런타임 주 저장소는 `(id TEXT PK, data JSONB, updated_at)` 제네릭 테이블 10종([db.js](../backend/src/db.js)). DB 미연결 시 `backend/data/*.json` 파일로 자동 폴백. 정규화 스키마([db/schema.sql](../db/schema.sql))는 **리포팅 타깃으로만** 보존.
- **배경**: 소규모·단독 개발. 스키마가 자주 바뀌는 초기 단계.
- **근거**: JSONB라 컬럼 마이그레이션 없이 필드 추가 가능(코드가 SSOT). 파일 폴백으로 DB 장애·로컬 개발에서도 앱이 안 죽음(가용성).
- **트레이드오프**: 관계 무결성을 애플리케이션 레벨(자연 키)로만 보장 → FK 강제 없음. 대량 집계·조인 쿼리엔 불리 → 그래서 관계형 스키마를 향후 이행 대상으로 남김([ROADMAP](ROADMAP.md)).
- **상태**: 유효. 리포팅 요구가 커지면 §관계형 이행 검토.

## ADR-02 · SSC 조회 도메인을 apex로 정규화(`www.` 제거)

- **결정**: 도메인 저장·조회 시 `cleanDomain`으로 스킴·포트·경로·**선행 `www.`**를 제거해 apex로 통일([server.js](../backend/src/server.js) `cleanDomain`/`normSscLookup`).
- **배경**: `www.posco.co.kr`로 조회 시 "Scope Denied"가 발생 — SSC 스코어카드가 apex(`posco.co.kr`) 기준으로 키가 잡히기 때문.
- **근거**: 저장·조회 양쪽에서 동일 정규화 → 목록·리포트 일관성, 스코프 오류 방지.
- **트레이드오프**: 서브도메인을 별도 스코어카드로 다뤄야 하는 경우엔 규칙 재검토 필요.
- **상태**: 유효.

## ADR-03 · 검증랩 증적 = "참고 PoC" (실 해소 아님)

- **결정**: 검증랩은 표준 격리 타깃에서 취약↔조치를 재현한 **참고 증적**일 뿐, 고객 운영환경의 실제 조치 완료를 의미하지 않는다. 모든 리포트·화면에 이 고지를 명시.
- **배경**: 파트너가 고객에게 "해결됨"으로 오인시키면 안 됨(책임·신뢰 문제).
- **근거**: 공식 해소 판정은 **SecurityScorecard 재스캔**으로만. 법적·신뢰 경계.
- **트레이드오프**: "증적이 곧 조치완료"라는 단순 메시지를 못 씀(설명 필요).
- **상태**: 절대 원칙. 문구 제거 금지.

## ADR-04 · AI Lab Builder 신뢰 경계 — LLM은 데이터만

- **결정**: Claude는 스키마 고정 **레시피(JSON 데이터)만** 생성. 실제 환경은 **결정적 렌더러**가 만들고, **검증 게이트 PASS + 관리자 승인** 후 **immutable 버전**으로만 채택([LAB_STUDIO](LAB_STUDIO.md)).
- **배경**: LLM이 실행 코드/Dockerfile을 만들어 서버가 실행하면 신뢰·보안 리스크.
- **근거**: LLM 출력을 "데이터"로 가두고 화이트리스트 아키타입만 렌더 → 실행 경로에 LLM 텍스트가 없음. 검증 의미(`verificationSemantics`)로 재사용 통제.
- **트레이드오프**: 자동화 범위가 제한적(Phase 1 = http_header·network). 새 아키타입은 사람 승인 필요.
- **상태**: 핵심 안전장치. 완화 금지.

## ADR-05 · 인증을 자체 구현(프레임워크 미사용)

- **결정**: scrypt 비밀번호 + 수동 서명 HS256 Access JWT(단수명) + 불투명 Refresh 쿠키(회전·재사용 탐지)([auth.js](../backend/src/auth.js)).
- **배경**: 보안 기반 계층을 외부 프레임워크에 기대지 않고 직접 설계(포트폴리오 의도 + 의존성 최소화).
- **근거**: Refresh 원문 미저장(SHA-256 해시)·회전·family 재사용 탐지로 탈취 대응. 통제 가능·투명.
- **트레이드오프**: 직접 유지보수 부담. 표준 라이브러리 대비 검증된 코너케이스 커버가 적을 수 있음 → 변경 시 신중.
- **상태**: 유효. 세션 로직 수정 시 재사용 탐지·회전 불변식 깨지지 않게 주의.

## ADR-06 · 권한 이중 게이트

- **결정**: 프론트 버튼 게이팅(`app.can`) + 백엔드 `requirePerm` 403 이중([authz.js](../backend/src/authz.js)). 역할 3종(admin/partner/viewer).
- **근거**: 프론트 게이팅은 UX일 뿐 — 실제 보호는 백엔드. 권한 거부는 보안 감사 기록.
- **트레이드오프**: 규칙을 두 곳에 반영해야 함(매트릭스는 authz.js가 SSOT).
- **상태**: 유효.

## ADR-07 · 설정 시크릿 AES-256-GCM 저장

- **결정**: SSC 토큰·Claude 키를 `app_settings`에 AES-256-GCM 암호화 저장, 원문 미반환(상태는 `****last4`)([settingsStore.js](../backend/src/settingsStore.js)). KEK는 `AUTH_ACCESS_SECRET`에서 용도별 salt로 파생.
- **근거**: DB 유출 시에도 토큰 노출 방지. Claude 키는 KEK가 약하면(기본값) 저장 차단(`WEAK_KEK`).
- **트레이드오프**: `AUTH_ACCESS_SECRET`가 KEK 근원 → 이 값 분실 시 저장된 시크릿 복호화 불가.
- **상태**: 유효.

## ADR-08 · 고객 전달 = 자립형 단일 HTML + 선택적 열람 암호 (개별 팩 게시 링크 폐지)

- **결정**: 전달 주력은 폰트·이미지 임베드 **자립형 단일 HTML**. 선택 시 리포트 전체를 **AES-256-GCM**으로 암호화(열람 시 WebCrypto 복호화)([reportHtml.js](../backend/src/reportHtml.js) `wrapEncrypted`). 기존 개별 팩 공개 게시 링크(`/api/public/shared`)는 **제거**.
- **배경**: 오프라인·로그인 없이 파일 하나로 전달하는 게 실무에 맞음. 개별 팩 링크는 인증 없는 공개 엔드포인트(보안 표면)이자 통합 리포트로 대체됨.
- **근거**: 오프라인 파일엔 만료가 실효 없음(우회 가능) → 확산 방지는 **암호화**로. 공개 엔드포인트 제거로 공격 표면 축소.
- **트레이드오프**: 오프라인 파일이라 회수·만료 불가(암호 아는 사람은 영구 열람). 만료·회수가 필요하면 서버 호스팅 방식이어야 함.
- **상태**: 유효(옵션 B로 확정).

## ADR-09 · 감사 로그 append-only · 민감값 미기록

- **결정**: 사용자·보안·시스템 이벤트를 append-only로 기록하되 **토큰·비밀번호 등 민감값은 절대 미기록**(상태·식별자만)([auditStore.js](../backend/src/auditStore.js)). 파일 폴백 시 최근 2000건 유지.
- **근거**: 감사성 확보 + 로그 유출 시 2차 피해 방지.
- **상태**: 유효. 로그에 값 남기지 말 것.

## ADR-10 · no-HA / RTO 10분 / 3-VM

- **결정**: 소규모 전제(동시 ~5명) — 고가용성 미적용. 복구 목표 RTO 10분, 컨테이너 `unless-stopped` 자동복구 + ESXi 스냅샷 롤백 + DB 백업/복구.
- **근거**: 규모 대비 과설계 회피. 장애는 자동복구·스냅샷·백업으로 커버.
- **트레이드오프**: 무중단(HA) 아님 — VM 손실 시 재배포 시간 소요.
- **상태**: 유효. 사용자·부하 증가 시 재검토.
